## Cause
Old probe, tests/integration/pty-plumbing.test.ts (bc0bf6a) probe(): `ls "$p" > "${dir}/before-$i.txt"` and `... after-$i.txt`.
The shell creates (truncates) the redirect target before `ls` runs and writes. The file exists and is empty until `ls` writes.
Old waitFor (same file, ~:307-309): `while (!existsSync(f) && Date.now() < deadline) sleep 20 ms` and it returns with no error. It tests only existence.
So the test thread sees the empty file and `lines(f)` returns `[]`.
Failure data (R2 and R3 before fix): `expect(received).toEqual(expected)`, expected `["s"]` (the listed skill), received `[]`, at pty-plumbing.test.ts:360:46 (claude). With the trigger: also at :329:46.
Second defect: a probe file that never appears makes waitFor return after 5 s with no message. The next read throws ENOENT with no hint.

## Fix (9f8ed92, already in the branch)
- probe writes to `*.tmp`, then `mv` to `*.txt` (atomic rename). A `.txt` file that exists is complete.
- `PROBE_DELAY` (seconds) sleeps between write and rename: it is the trigger for the race.
- waitFor throws `waitFor: <file> did not appear within 5000 ms`.
